## 已确认问题

### A01 · P2 · 数据表格排序按钮会提交外层表单

位置：`src/components/ui/data-table.tsx:55`。

- 条件：下游将 DataTable 放入一个 form，例如设置编辑页或批量配置表单。
- 原因：排序使用原生 button，却没有 `type="button"`，在 form 中默认执行提交。
- 复现：在组件页为 `.data-specimen .data-table` 包裹 form，为 submit 计数并 preventDefault，然后点击列排序。计数从 0 变为 1。
- 影响：只想改变显示顺序的操作可能触发保存、校验或页面导航。当前演示中表格不在 form 内，现有测试未覆盖该组合。
- 建议：为排序按钮显式设置 type，并增加“表单内排序不触发 submit”的行为测试。

### A02 · P2 · 实验详情关闭后丢失键盘焦点

位置：`src/pages/workspace.tsx:44`；相关实现 `src/components/ui/dialog.tsx:5`。

- 复现：键盘聚焦“查看 EXP-024 详情”，Enter 打开，Esc 关闭；此时 `document.activeElement === document.body`。
- 原因：详情采用受控 Dialog，没有 Radix Trigger，也没有传 returnFocusId 或保存触发元素。新建弹窗已提供 returnFocusId，详情尚未提供。
- 影响：键盘用户需要重新寻找原记录，名称按钮和图标按钮两个入口均需要正确恢复。
- 规范：`DESIGN.md:116` 明确要求没有 Radix Trigger 的受控调用自行恢复焦点。
- 建议：记录实际触发元素的 ref，关闭时恢复；如该行已不可见，则聚焦合理的表格或页面入口。补充两个入口的关闭测试。

### A03 · P2 · 英文官网在 320px 视口横向溢出

位置：`src/design-refresh.css:33`、`:471`、`:504`。

- 复现：英文官网、320px 视口。`document.documentElement.scrollWidth` 为 337px，超出视口约 17px。
- 直接来源：三列 `.brand-values` 仍使用 `repeat(3, 1fr)`；英文内容的最小宽度与两侧留白、列间距相加超过可用宽度。右侧 `.value-statement` 的右边界约为 337.16px。
- 影响：极窄屏或等效放大条件下产生整页横向滚动。这不是允许局部横向滚动的数据表格。
- 建议：窄屏减少列数或使用可收缩网格并处理长单词；增加 320px 中英文页面溢出测试。不要用全局 overflow-x:hidden 隐藏内容解决。

### A04 · P2 · 品牌导出脚本依赖未在项目中声明

位置：`scripts/render-brand.cjs:2`；`package.json`。

- 复现：当前按仓库依赖运行 `node scripts/render-brand.cjs`，立即报 `Cannot find module 'sharp'`。
- 原因：脚本直接 require sharp，但 package.json / lockfile 没有提供该依赖。README 的 npm 安装步骤不能准备完整品牌导出环境。
- 影响：修改源 logo 或审核页面后，无法按 DESIGN.md 的命令重新生成配套 PNG / PDF。
- 建议：声明所需 Node 依赖、明确 Python 依赖与浏览器准备方式，提供独立的品牌构建命令和依赖预检；用干净环境验证，而非依赖历史临时目录。

### A05 · P2 · PPT 生成默认引用失效的技能路径

位置：`scripts/build-research-deck.mjs:7`、`:9`。

- 复现：当前运行 `node scripts/build-research-deck.mjs`，报 ERR_MODULE_NOT_FOUND，目标为 presentations/26.1007.11041 下的 artifact_tool_utils.mjs；该路径已经不存在。
- 原因：默认值固定到个人目录及已过期的插件版本。虽然模板 README 提到环境变量覆盖，但默认命令在当前机器已不能运行，也没有可执行的发现 / 预检步骤。
- 影响：模板成品仍能使用，但后续修订不能按默认工具链重建。
- 建议：通过明确配置或当前 runtime 查询解析依赖，缺少配置时给出具体诊断；将所需版本和准备步骤写入可复现的构建说明。运行前验证所有辅助文件存在，避免进入导出后才失败。

### A06 · P2 · PPT 页眉的完整双语 logo 小于 VI 最小文字要求

位置：`scripts/build-research-deck.mjs:23`；资产构造见 `scripts/build-brand.py:78`。

- 原始双语组合的 viewBox 宽度为 850，最小英文字号对应 22 个源坐标单位；PPT 页眉将其显示为 148px 宽。
- 当前 PPT 包中图片有效宽度为 111pt，英文约为 `22 / 850 × 111 = 2.87pt`；中文约为 5.48pt。
- `DESIGN.md:27` 规定完整名称组合最小文字不低于屏幕 12px / 印刷 7pt。当前页眉显著低于印刷要求，画廊预览也能看到名称过小。
- 影响：正式汇报或印刷时名称难以辨认，与本 VI 的尺寸约束不一致。
- 建议：页眉使用适合小尺寸的 IDRL 字标组合或图形，完整双语名称在封面 / 结束页按可读尺寸展示；同时复核图形本身尺寸和外部净空，重新导出 PPT 与预览。
